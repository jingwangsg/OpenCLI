# 如何把一个应用改造成 API 命令

本文记录 OpenCLI 在小红书、Google Maps 和旅行查询迁移中验证过的方法。这里的 API 化指：命令通过 HTTP、站点自身的签名客户端或本地存储接口完成操作，不依赖页面跳转、点击、滚动或读取当前显示的列表。

浏览器仍可以提供登录 Cookie 和站点签名环境。这与通过页面控件执行业务操作是两件事。

## 1. 先固定功能范围与验收标准

先列出现有命令、参数、返回字段、分页要求和外部副作用。迁移不能只覆盖第一页，也不能为了适配新接口而丢掉原来的字段。

本次小红书范围是主站身份、登录状态检查、搜索及筛选、Feed、笔记、评论及回复、用户笔记、收藏、点赞、通知、媒体下载、关注/取消关注、点点问答。用户明确排除了 `creator.xiaohongshu.com` 下的统计、发布、草稿和内容管理；这些命令不属于本次 API 迁移的验收范围。

Google Maps 范围是地点搜索与详情、收藏列表与备注读取、保存地点、修改地点备注和列表描述，不包含新增路线、评论或照片管理能力。

| 验收项 | 应检查的事实 |
| --- | --- |
| 参数 | 查询、筛选、日期、币种、人数和目标 ID 真正进入请求 |
| 身份 | 返回对象属于所请求的地点、笔记、作者或列表 |
| 完整性 | 达到请求数量，或服务端明确表示已结束 |
| 字段 | 保留原命令字段；时间、价格等格式变化需说明 |
| 错误 | 登录、权限、网络、协议变化、空结果分别处理 |
| 写入 | 目标明确、不会重复提交、重新读取后确认结果 |
| 页面行为 | 测试禁止调用 goto、click、scroll 和页面等待 |

HTTP 方法不决定副作用。Maps 的 `entitylist/createitem`、`updateitem` 和 `update` 都使用 GET，但它们是写操作。

## 2. 浏览器 profile、站点身份和站内账号分开验证

先运行：

```bash
opencli profile list
opencli --profile edge doctor
```

`doctor` 证明 Bridge 可连接，不证明任何网站已登录。Cookie 存在也不等于有效身份。用站点身份接口确认，例如小红书 `/api/sns/web/v2/user/me` 的 `guest` 和用户 ID。

小红书创作者中心接口返回数据，不能代替主站身份验证。主站可以显示服务端预渲染的卡片，同时身份接口仍返回访客；这次就观察到了这种情况。

同一个 Edge profile 也可以登录多个 Google 账号。Maps URL 的 `authuser` 必须传递到读请求、写入上下文和验证请求。本次同一列表在两个账号下分别返回访客和拥有者角色。不能把浏览器 profile 的账号名称当成 Google 账号索引。

命名 profile 别名应保持稳定。不要直接复制 Cookie 数据库来“合并登录”，也不要把 Cookie、CSRF、签名或账号列表写入文档、fixture 和提交记录。

## 3. 从真实请求确定接口

依次检查网络请求、页面初始化数据、已加载的前端 bundle。bundle 中的地址是候选，不能仅凭字符串出现就认定它是可用契约。

一次改变一个输入，比较请求和响应：

1. 记录查询 A 的请求方法、路径、参数结构及响应形状。
2. 改为查询 B，确认哪个字段控制查询。
3. 翻页，确认是页码、游标还是 offset。
4. 将返回的 ID 与页面上的目标对应起来。
5. 对只读接口重放至少两个非空输入，再验证真正的空结果。

记录结构和结果数量即可，不保存原始授权头或带私人备注的请求 URL。网络抓取器可能在读取时清空队列；安装捕获必须先于动作，必须等待相关响应完成，不能把没有 body 的条目当成空结果。

## 4. 在最小必要的环境中调用

| 调用方式 | 适用条件 | 本次例子 |
| --- | --- | --- |
| Node HTTP | 请求本身可复现，不需要页面运行时 | Maps JSON 读接口 |
| Node HTTP + profile Cookie | 站点会话及正常请求头足够 | Trip/Ctrip 酒店接口 |
| 页面中的第一方客户端 | 签名依赖站点运行时 | 小红书主站 |
| HTTP 初始化数据 + API | 初始化文档提供请求上下文 | Maps 写操作的账号和操作 token |
| IndexedDB API | 数据实际只存在浏览器本地 | 创作者草稿，已排除本次范围 |

不要手写站点的风控算法或复制过期签名。小红书用自己的 webpack HTTP 客户端生成签名、转换请求字段，并解析响应。模块数字 ID 会随构建变化，因此通过已验证的语义特征定位模块，缺失时明确报错。

业务命令不得为了加载签名环境而自动导航。先准备登录标签页，再运行命令：

```bash
# 在所选 profile 的小红书主站标签页上绑定
opencli --profile edge browser xiaohongshu-web-api bind
opencli --profile edge xiaohongshu whoami
opencli --profile edge xiaohongshu search '旅行' --limit 35 -f json
```

主站命令使用持久的 `site:xiaohongshu` 会话；已有正确站点环境时直接使用，否则使用显式绑定的标签页。签名环境必须已完成初始化。现场观察到隐藏标签页中的签名请求挂起，因此命令会激活已有的 adapter 标签页；不改变 URL，也不点击业务控件。显式绑定的用户标签页需要保持可运行。超时不能被解释为“没有数据”。初次准备环境和命令业务执行应分开。

## 5. 完整保留请求上下文

减少参数之前先复现原请求，再逐项删除并验证。不能只留下地址，丢掉 Cookie、User-Agent、CSRF 或签名后，就认定接口不可用。

本次具体例子：

- Booking GraphQL 在缺少浏览器 User-Agent 时返回 HTTP 200 的 Redirect 分支；补齐当前会话上下文后才返回结果。
- Google Flights 的简化上下文曾返回 HTTP 200 空结果；完整搜索上下文能返回有效航班。
- 小红书旧签名函数与当前页面的签名客户端并不等价。使用第一方客户端后，主站身份和搜索可直接读取。
- Maps 不同写操作使用不同 token。当前实现通过同一账号的 HTTP 初始化文档读取它们，在内存中使用，并验证 endpoint 和 `authuser` 一致。

请求地址必须限制到明确的站点和接口范围。自动跳转可能把凭证带到错误的位置；API 请求应拒绝意外跳转。媒体下载另有边界：小红书主站 Cookie 不应发送给 CDN。当前实现校验媒体域，并将 API 给出的 HTTP CDN 地址升级为已实测可用的 HTTPS 地址。

## 6. 按协议解析，不把字符串形状当成数据

Google Maps 使用带 XSSI 前缀的 JSON 位置数组，有时外层还有 `d` 字符串封装。先解包，再检查位置上是否存在稳定身份和必要字段。不要递归搜遍任意数组来凑结果，那会混入推荐、广告或其他对象。

地点 ID 的两个部分是 64 位值。列表接口既可能返回有符号十进制字符串，也可能返回无符号字符串。必须使用 BigInt，先检查范围，再通过 `BigInt.asUintN(64, value)` 转成规范十六进制 ID；不能经过 JavaScript Number。

Maps 写入的 `pb` 是有类型和层级的协议。`m` 后面的数值是子树中的字段数量；Unicode 文本用 URL-safe Base64 的字符串编码。应对照官方构造器和真实请求核对完整字段顺序与计数，不能只检查 URL 包含几个关键片段。

其他协议也需要独立验证：

- Trip 航班响应是 SSE，必须解析完整事件流。
- Fliggy 多阶段查询有服务端 `isContinue` 和下一轮等待时间，不能只取第一轮。
- 本次 Google Flights RPC 的帧长度是 JavaScript UTF-16 字符数加两处 framing 换行；这只是该端点的观察结果，不能推广到其他 RPC。
- GraphQL 的 HTTP 200 仍可能包含 `errors` 或非结果分支。

## 7. 以服务端信息判断分页结束

Maps 搜索的普通 `start=20` 会重复第一页；实际分页字段是 `pb` 中的 offset。搜索结果中的第一条可以是请求元数据，只有识别到这种结构才能跳过；其他缺失 place payload 的记录必须报错。

Maps 列表返回服务端总数。分别请求 2 条和 500 条时，返回数量不同，总数仍相同。读取完整列表后必须验证总数、唯一地点数及每条备注，不能仅以“少于 500 条”推断结束。

小红书搜索使用页码与 `hasMore`；用户、收藏、点赞及评论使用服务端游标。评论的顶层分页和每条评论的子回复分页是两层独立流程。`--limit` 只限制顶层评论，子回复不占这个数量。

通用失败条件包括重复游标、重复整页、宣称有下一页却没有数据、超出页数上限、后续页网络失败。出现这些条件时不能返回已累计的部分结果并声称成功。

## 8. 写操作必须有独立的完成证据

写入前读取目标状态，检查身份和权限。已经达到目标状态时返回 unchanged；保存一个已存在的地点不能清空其备注。

提交后重新读取服务端状态，不用当前控件、请求 echo 或历史网络条目作为确认。Maps 还检查其他成员、原有备注、列表描述和数量，避免把意外改动或并发变化报告为成功。

提交超时不等于未提交。关注操作发生异常后会单独读取关系；若无法确认，返回结果不确定，禁止自动重放。Maps 同样不自动重试写请求。

### 已实施的执行接口变更

原 `Page.evaluate` 在 `target_navigated` 后会再次执行脚本，包含 POST 时可能重复提交。此次增加可选 `IPage.evaluateOnce` 和 Browser Bridge `Page.evaluateOnce`：复用现有 `exec` 请求及命令日志，跳过页面导航错误后的第二次执行。现有 `evaluate`、调用参数和 Bridge wire protocol 不变。

小红书关注和点点调用使用此入口；不支持它的运行环境在提交前报错。测试模拟发送后失去导航上下文，确认只分发一次。

真实写入测试需要明确目标及允许的改动次数。迁移实现本身不是随意关注用户、修改私人备注或发布内容的授权。可以先生成准确预览，再对获准的测试目标进行一次提交和独立读回。

## 9. 会话生命周期也属于正确性

本次复现了绑定标签页被原 owned lease 超时清空的问题。修复位于 Bridge：释放 lease 时保留仍被其他 lease 引用的标签页；worker 恢复时先恢复全部引用，再处理过期项；绑定和释放串行执行，避免在等待 detach 时发生竞争。

这类问题应修复在会话所有权层，而不是给某个业务 adapter 随意加长 timeout。扩展源代码的修复需要构建并重新加载扩展后才作用于运行中的 Bridge。

## 10. 验证与交付

测试应调用注册的生产命令入口和实际传输路径，并使用合成的敏感字段。不要只测解析函数，也不要把真实 token 或私人列表存进 fixture。

建议固定这些检查：

```bash
npm run build
npm run typecheck
npx vitest run --project adapter clis/xiaohongshu clis/google-maps
npx vitest run --project unit src/browser/page.test.ts
npx vitest run --project extension extension/src/background.test.ts
npm run check:typed-error-lint
npm run check:silent-column-drop
opencli validate xiaohongshu
opencli validate google-maps
```

保留原来的公共列。若通用验证器限制最多 12 列，而已有命令公开 13 列，记录冲突，不能为了通过检查悄悄删除字段。已有 lint 或类型错误也要与本次引入的问题分开确认。

2026-09-29 的现场验证包含：小红书搜索与 Feed 各 35 条、筛选查询、收藏与点赞、两个作者的笔记、两篇笔记及嵌套评论、点点回答及来源、10 张图片和 1 段视频下载；Maps 搜索分页、两个地点详情，以及 113 个列表地点和备注。

Maps 三类写入和关注关系变更有生产入口合成测试，包括副作用次数、未知结果、账号绑定和独立读回。真实账号写入尚未执行，不应把这部分描述成已经通过服务端现场验收。

同一逻辑写操作可能借用已绑定的 browser 标签页。它的 pending 请求也需要维持原 adapter 写租约，否则长回答超过租约 TTL 后可能被第二个任务打断。对此保持既有绑定 surface 和请求格式，只在 daemon 内把同一 run 的跨 surface 请求关联到已有租约，并在请求完成时更新存活时间。
